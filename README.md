# GE2 Caravan

English practice platform for GE2 (CEFR B1) Group 9, UTAS Salalah — teacher: Maher Kashoob.
Students log in with their College ID, get Claude-written exam practice in the official UTAS format, play class games, write and get feedback, and build project slides.

**Owner / product decisions: the teacher. Engineering: Claude (this repo is shared between Claude chats and Claude Code).**
Working rules live in the claude.ai project "26FL teaching" (docs `GE2-Caravan-how-to-work-with-Claude.md`, `GE2-exam-format-rules.md`, `GE2-Caravan-product-spec.md`). Short version: try → catch → finally — build it, hunt your own errors before the teacher sees them, publish and verify, never say "done" for something not run.

## The protocol (what a game or page sends to the server)
POST JSON to the front door. Every call carries `kind` and, after login, `token`.
- `login {id, pin, device}` → `{ok, token, name, role}`; `set_pin` first time.
- `exam {token, prompt, skills, len, game}` → `{ok, text}` where `text` is Claude's JSON exam (`texts[]`, `questions[]` with `type` tfng|abc|word|head|box|table, `q`, `options`, `answer`, `evidence`, `why`, `skill`). Daily limit 12/student; the server answers `{ok:false, code:"limit"}`.
- `bank {token, data:{skills,len,exclude}}` → a saved exam `{ok, spec, id, title, by}`.
- `result {token, type, exam, right, total, grade, score, won, skills[{id,name,r,n}], weakest, badges}` → XP, level, badges.
- `profile {token}` → `{profile, board, today:{exams,limit,writings,wlimit}}`.
- `coach`, `writing`, `tasks`, `project_save/get/list`, `teacher_*` — see `supa/caravan/index.ts`.
The Studio opens a game page with `#play&s=TOKEN~ID~ROLE~NAME~SHORT&x=SRC.LEN.TITLE`; `games/caravan-bridge.js` parses that and does the calls above. A game built elsewhere must use the same hash and the same calls (the 3D Rally needed an adapter — see the `RALLY_BRIDGE` script at the top of its page).

## Local build and tests
`npm install` once, then `npm run build:studio`, `npm run test:syntax`, `npm run test:local`. Built pages go to `build/outputs/`, screenshots and logs to `build/tmp/` (both gitignored; override with `CARAVAN_OUT` / `CARAVAN_TMP`). Production tests stay blocked unless `CARAVAN_LIVE=1`. Details: `tests/README.md`.

## Build and publish (from a workspace that has the Cloudflare secrets)
1. Edit sources. Studio: `python3 caravan/build_class.py` (→ `build/outputs/`). Quests: `python3 caravan/quests/build.py`. Games: copy `caravan/games/*.html` to the slot file in `build/outputs/` (`CARAVAN_OUT`).
2. Syntax-check every inline `<script>` (`new Function(src)`), run the Playwright test, look at a screenshot at phone width.
3. `bash caravan/publish.sh` (reads `caravan/secrets/cf_token`, `cf_account` — never committed).
4. Run the n8n sync workflow `d70f3mpVS0pjJSXF`, wait ~60 s, `python3 caravan/verify_live.py <rows.json>` → 11 × IDENTICAL.
5. Tell the teacher: "live — close the tab and reopen the link".

Supabase: project `ge2-caravan` (eu-central-1); deploy `supa/caravan/index.ts` as function `caravan` (verify_jwt off) after `tsc` passes. Secrets (ANTHROPIC_API_KEY, IMPORT_KEY, PEPPER) are set in the Supabase dashboard by the teacher — never in code, never in chat.

## Hard rules
- Printed student sheets ≥ 13 pt, ≤ 3 pages, official exam format, nothing reused, no Arabic unless asked.
- Exams look like the UTAS final (`GE2-exam-format-rules.md`).
- Nothing is used in class untested by the teacher on his own phone the day before; always a paper fallback.
- Keep the teacher's PIN, API keys and student personal data out of this repo (`.gitignore` whitelist; `roster*.json` and n8n exports are excluded on purpose).
